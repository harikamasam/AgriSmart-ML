# ML Based Crop Recommendation System

This terminal-only project compares three leakage-free feature-selection approaches with three tree-based classifiers. It preserves the domain-based agricultural feature engineering already present in the project.

```text
Agricultural Dataset
        ↓
Preprocessing + EDA + fixed stratified split
        ↓
Domain-Based Agricultural Feature Engineering
        ↓
{ Mutual Information | RFE | Mutual Information + RFE }
        ↓
{ XGBoost | LightGBM | Random Forest }
        ↓
Nine experimental results → Best combination → Terminal crop recommendation
```

There is no web interface, Flask, API, image segmentation, or K-Means clustering.

## Dataset

The actual repository dataset is `data/crop_data.csv`:

- 2,200 samples
- 7 original agricultural input features
- 22 crop classes, 100 samples per class
- Target column: `label`
- Inputs: `N`, `P`, `K`, `temperature`, `humidity`, `ph`, `rainfall`
- Missing values: 0
- Exact duplicate rows removed: 0

The implementation validates the schema rather than silently assuming a different target or input format.

## Preprocessing and fairness checks

The project creates one stratified 80/20 split with `random_state=42`: 1,760 training rows and 440 testing rows. The target label is excluded from the input matrix. All nine experiments reuse exactly this split.

The executed checks found:

- Exact feature overlap between train and test: 0 rows.
- Near-identical overlap after rounding all seven input features to two decimal places: 0 rows.
- MI and RFE fitted on training data only: yes.
- Test data used for feature selection or model fitting: no.
- Hyperparameter selection using the test set: no.

## Domain-based agricultural feature engineering

`src/feature_engineering.py` transforms the seven original inputs into the original values plus eight meaningful derived features:

| Feature | Purpose |
|---|---|
| `N_P_Ratio` | Relative nitrogen/phosphorus availability. |
| `N_K_Ratio` | Relative nitrogen/potassium availability. |
| `P_K_Ratio` | Relative phosphorus/potassium availability. |
| `Total_NPK` | Overall macronutrient amount. |
| `Mean_NPK` | Average macronutrient level. |
| `Nutrient_Balance` | Minimum-to-maximum balance across N, P and K. |
| `Temperature_Humidity_Index` | Combined thermal and humidity condition. |
| `Rainfall_Humidity_Index` | Combined rainfall and humidity water-availability condition. |

Ratio division is safe when a denominator is zero. The resulting training and testing matrices each have 15 columns.

## Feature selection

- MI selects the top 10 features by `mutual_info_classif` score. The scores are fitted only on the training matrix.
- RFE selects 10 features using a reproducible 250-tree Random Forest estimator because it provides `feature_importances_` and is classifier-independent for the comparison. The RFE estimator is fitted only on training data.
- MI+RFE first retains 12 MI candidates, then RFE selects the final 10 features from those candidates.

The selected feature lists are recorded in `results/model_comparison.csv`; MI scores and RFE rankings are in `results/feature_selection/`.

Selected features from the executed run:

- MI: `humidity`, `Rainfall_Humidity_Index`, `K`, `rainfall`, `Total_NPK`, `Mean_NPK`, `P`, `P_K_Ratio`, `Temperature_Humidity_Index`, `N_K_Ratio`
- RFE: `N`, `P`, `K`, `humidity`, `rainfall`, `P_K_Ratio`, `Total_NPK`, `Mean_NPK`, `Temperature_Humidity_Index`, `Rainfall_Humidity_Index`
- MI+RFE: `humidity`, `Rainfall_Humidity_Index`, `K`, `rainfall`, `Total_NPK`, `Mean_NPK`, `P`, `P_K_Ratio`, `Temperature_Humidity_Index`, `N`

## Classifiers and parameters

XGBoost builds trees sequentially; later trees correct earlier errors. It used `n_estimators=250` boosting rounds, `learning_rate=0.08`, `max_depth=6`, `subsample=0.9`, `colsample_bytree=0.9`, `objective='multi:softprob'`, `eval_metric='mlogloss'`, `random_state=42`, and `n_jobs=1`.

LightGBM is also a gradient-boosted tree method, using histogram-based learning for efficient training. It used `n_estimators=250`, `learning_rate=0.08`, `max_depth=6`, `num_leaves=31`, `subsample=0.9`, `colsample_bytree=0.9`, `objective='multiclass'`, `random_state=42`, `verbosity=-1`, and `n_jobs=1`.

Random Forest builds many trees independently using random samples/features and combines their votes. It used `n_estimators=250`, `max_depth=None`, `max_features='sqrt'`, `random_state=42`, and `n_jobs=1`.

The three classifiers were not separately tuned against the test set. The same selected features, split, target encoding procedure, and evaluation procedure were used for each corresponding feature-selection branch.

## Actual nine-experiment results

Weighted precision, recall, and F1-score are reported. These values were generated by executing `python -m src.main` on the repository dataset.

| Feature Selection | Model | Accuracy | Precision | Recall | F1 |
|---|---|---:|---:|---:|---:|
| MI | XGBoost | 99.09% | 99.11% | 99.09% | 99.09% |
| MI | LightGBM | 99.55% | 99.57% | 99.55% | 99.55% |
| MI | Random Forest | 99.32% | 99.37% | 99.32% | 99.32% |
| RFE | XGBoost | 99.09% | 99.15% | 99.09% | 99.09% |
| RFE | LightGBM | 99.32% | 99.35% | 99.32% | 99.32% |
| RFE | Random Forest | 99.09% | 99.15% | 99.09% | 99.09% |
| MI+RFE | XGBoost | 99.32% | 99.35% | 99.32% | 99.32% |
| MI+RFE | LightGBM | 99.09% | 99.12% | 99.09% | 99.09% |
| MI+RFE | Random Forest | 99.09% | 99.15% | 99.09% | 99.09% |

Best combination: **MI + LightGBM** with **99.55% test accuracy**. The best model is saved as `models/best_crop_model.pkl` and the terminal prediction module loads the best trained bundle from the current run.

The high scores are measured results, not claims of universal superiority. They may reflect the strong separability of this balanced crop dataset by its NPK, climate, rainfall, and derived interaction/ratio variables, together with the capacity of tree ensembles. The duplicate and rounded near-duplicate checks found no train-test overlap, but external regional validation would still be needed before agricultural deployment.
